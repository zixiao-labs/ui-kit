# 新中式设计指南

新中式不是给通用界面贴传统元素。先说清产品和任务，再从一种有依据的空间、器物、书刊或地方材料中提炼**构图、文字和材质的关系**。去掉纹样以后，设计仍应该认得出来。

## 先划定其他指南的职责

1. 用户指定的品牌、参考、交付范围与已有产品约束优先。工作台加功能时延续有效设计，不借「新中式」重做整站。视觉选择与可用性冲突时，保留可用性，调整视觉手法。
2. 本指南负责新中式的视觉方向。借 **Oil UI** 的方法收敛：产品事实 → 一句设计方向 → 灰度结构 → 实图评审。先看主任务是否成立，再看画面是否成立。默认深化一个方向，不自行扩成多版比稿。
3. **UI/UX Pro Max** 用于键盘、触屏、可读性、反馈和响应式检查。搜索结果是候选，不覆盖已经确定的风格、中文字体或主题 token。
4. **Taste Skill** 用来检查文案具体、真实内容、网格对齐、素材加载与浏览器表现，**不用来分配风格**。不随机抽配色、字体或 hero，不用全局禁紫覆盖真实品牌色，不导入 Taste starter、全局 CSS 或动效层。工作台、目录和表单不为门禁变成一屏一节，不补营销 CTA、照片、入场、强制悬停抬升或滚动场面。落地页可以有 hero 或一处由内容支撑的叙事，不设固定屏高或动效配额。若运行 Taste 检查，分别记录可用性问题和不适用的模板规则；不要修改检查器或把未通过写成通过。

不要求安装以上三个 Skill，也不使用它们的脚本、服务或素材作为依赖。

可先读[两种任务示例](references/react-ui.md#怎样使用这份-skill)。需要查询七种风格、运行时 API 或配色时，优先读取已安装 React 包的 `docs/`；也可用 Context7 库 `/zixiao-labs/ui-kit` 查询。规则与示例随包自带，不把 Context7 作为必需服务。

## 从方向到页面

1. **记录依据。** 写用户、任务、真实内容、设备和素材，再定一句方向，例如「让可筛选的器物档案像石白展墙上的目录：信息按年代分组，黛青留给打开档案。」明确首屏主角和主动作。没有可靠素材时用已有内容、能溯源的素材或文字构图，不把假图和编造的史料当成真实证据。
2. **先排灰度。** 工作台让目录、筛选、对象和操作尽快可见；留白用来区隔信息，不挤掉首屏任务。档案、图录和文章用书页式边注、图注或章节层次安排阅读，窄屏改为顺读。落地页先说清品类和主动作，让真实产品、作品或场所领衔，无图时不强塞一张氛围图。
3. **选一个材质方向。** `hepo`（鹤坡）取石白 / 墨瓦、黛青 / 浅水青和浅木，适合档案、阅读或清晰的工具面板；`hepo-interior`（鹤坡·室内）取暖石白 / 暖炭灰、红木与浅香槟，适合室内陈列、展签与接待。已定的品牌也可以是主角：沿用它的风格和适量强调色，不拿另一套预设覆盖。详见 [React 接入与验收](references/react-ui.md)。
4. **把颜色和文字分工。** 中性表面承载内容，主色给主操作，木色或浅香槟给辅助面与选中态；正文、错误、焦点各用自己的语义色。宋体用于短标题和少量展示文字，黑体保正文、控件和密集信息；不用书法体做小字，不照搬拉大字距的英文标题。细边、对齐和小圆角优先于一排卡片或粗框。深色另验表面、主操作、悬停和选中，不把浅木和香槟直接压成低明度黄褐。
5. **最多选一种主要装饰。** 默认为无。纹样可以解释对象、标识区域或收束边缘，不能铺满表单、正文或数据层；不把多种回纹、印章、水墨、灯笼、金边叠成「中式」。默认沿用组件反馈与 `prefers-reduced-motion`，不开玻璃、倾斜、光晕或 GPU 效果来证明设计感。

## 收尾

- 在真实页面看代表性的桌面、窄屏及项目支持的明暗状态：中文断行、页边、焦点、选中和带底纹的文字不能退步。正文及普通标签对比至少 4.5:1；必要的控件边界和状态指示至少 3:1。
- 用键盘走完主流程，检查加载、空结果、出错和完成状态是否能读懂、能继续操作。触控主要操作尽量达到 44×44 CSS px，不靠颜色或 hover 传达唯一信息。
- 分开报告**视觉还保留了什么依据**与**实际验证了哪些任务和状态**。没有看实图就写未验视觉，脚本通过不能替代浏览器。
- 新页面或范围较大的改版可用随包的 [审稿脚本](scripts/check-plan.mjs) 检查设计卡是否缺少主任务或误借 Taste 规则；[字段及示例](references/react-ui.md#可选审稿脚本)。日常小改不用另建计划文件。
